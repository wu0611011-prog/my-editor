# 3D 吃豆人 (Pac-Man Vibe) 编程开发总结报告

## 1. 项目背景与目标
本项目旨在开发一个基于 Three.js 的 3D 版吃豆人网页小游戏。核心目标是实现流畅的 3D 渲染、基础的游戏逻辑（移动、碰撞、得分、关卡切换）以及增强视觉与听觉反馈的“汁性（Juice）”设计 [cite: 记忆回溯.md]。

## 2. 核心技术架构
- **渲染引擎**: 使用 Three.js (v0.160.0) 处理 3D 场景、灯光与材质 [cite: 记忆回溯.md]。
- **物理与碰撞**: 基于简单的坐标边界检测实现玩家与墙壁、豆子及幽灵的碰撞逻辑 [cite: 记忆回溯.md]。
- **视觉反馈**:
    - 使用 `ShaderMaterial` 编写自定义着色器，实现随玩家位置动态变化的地板光晕效果 [cite: 记忆回溯.md]。
    - 引入基于 `Math.sin` 的正弦波动画，使墙壁浮动、玩家缩放，增加灵动感 [cite: 记忆回溯.md]。
- **音频系统**: 利用 Web Audio API 实时生成合成音效，根据得分动态调整音调频率 [cite: 记忆回溯.md]。

## 3. 关键迭代与优化
### 3.1 场景重置机制 (Light Fix)
- **问题**: 在关卡切换或重启时，容易出现场景变黑或对象残留。
- **解决方案**: 在 `restartGame` 函数中通过 `while(scene.children.length > 0)` 彻底清空场景，并重新初始化灯光 (`createLights`) 和地板，确保渲染环境的一致性 [cite: 记忆回溯.md]。

### 3.2 编码行为准则 (CLAUDE.md)
- 引入了**简洁优先**和**目标导向**的开发准则 [cite: Claude.md]。
- 强调“只碰必须改的地方”，避免过度设计，确保代码逻辑的纯粹性 [cite: Claude.md]。

### 3.3 第二关性能与体验优化
- **问题**: 第二关由于目标分数较高，原有的豆子刷新速度过慢（上限5颗，2%触发率），导致玩家长时间无豆可吃 [cite: Claude.md]。
- **优化**: 实施了关卡差异化刷新策略：
    - **第一关**: 上限 5 颗，刷新概率 2% [cite: Claude.md]。
    - **第二关**: 上限提升至 **12 颗**，刷新概率提升至 **5%** [cite: Claude.md]。
- **效果**: 显著提升了游戏节奏，确保了高难度关卡下的补给流畅度。

## 4. 后续开发规划
- **AI 升级**: 将幽灵从随机游走升级为带有路径搜索（如 A* 或 简单追踪）的追踪算法。
- **玩法扩展**: 增加“能量大豆子”，使玩家获得反杀幽灵的能力。
- **关卡生成**: 从硬编码地图数组转向程序化随机迷宫生成。
